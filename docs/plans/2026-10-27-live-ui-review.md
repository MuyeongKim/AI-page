# 2026-10-27 결과 화면 정리와 실시간 알림·저장 재검토

사용자 요청: 결과 버튼 통합, 상황판 연계 도구 하단 분리, 실시간 알림·장면 저장 타당성과 사용성 재검토·보완. 버전 V26.1018과 기존 탐지·저장 기록을 유지하며 EXE는 만들지 않는다.

## 화면 기준과 결정

현재 PySide6 화면의 색상·버튼·스크롤·하단 실행 영역을 기준으로 한다. 사용자 지정 버튼명과 작업 결과 탭 하단 배치를 우선하고 Refero Design의 폼 오류·입력 초안·포커스·상태 안내 원칙을 적용한다. 새 의존성이나 디자인 체계는 추가하지 않는다.

| 결정 | 근거와 동작 |
| --- | --- |
| 결과보기 [원본과 비교] 하나로 통합 | 사용자 요청. 사진은 비교로 시작하고 탐지본만 보기·사진 이동·100% 보기를 유지한다. 영상 선택 시 영상 결과보기로 표시한다. |
| STAY UP 상황판 연계 섹션 | 작업 결과 하단에 파일 내보내기·폴더 연결·해제·현재 상태를 모은다. 사진 연계 규격·동작은 유지한다. |
| 최근 알림·저장 결과·저장 오류 분리 | 프레임 갱신이나 구간 선택으로 중요한 상태가 덮이지 않게 한다. 오류는 다음 실행 준비 전까지 남긴다. |
| 구간별 초안 보존 | 다른 구간을 선택해도 메모를 유지한다. 파일 저장은 기존 메모 저장 버튼과 워커 확인이 필요하다. |

## 재현한 문제와 수정

1. 구간 1에 미저장 메모 입력 → 구간 2 선택 → 구간 1 복귀 시 입력이 사라졌다. 구간별 초안을 보존하고 미저장 상태를 표시한다.
2. 장면 쓰기 오류 → 다음 정상 이벤트를 받으면 저장 실패 표시가 장면 수로 바뀌었다. 별도 오류 영역을 유지하고, 실제 JPEG 저장 결과를 별도 신호로 확인한다.
3. 추론 중 수동 저장 요청이 들어오면 요청 전에 받은 프레임을 저장할 수 있었다. 요청과 프레임 수신의 단조 시각을 비교해 요청 이후 프레임부터 사용한다. 새 프레임 없이 종료하면 저장하지 못한 요청을 알린다.
4. 구간·장면의 시각을 추론 완료 뒤에 만들었다. PC에서 프레임을 읽은 시각을 전달해 기록한다. 기체의 촬영 시각·실제 영상 지연·GPS를 확인한 것으로 표현하지 않는다.

## 알림·저장 타당성 판단

- 사람 후보의 별도 신뢰도·연속 분석 프레임·반복 억제와 실제 미탐지 관측에 따른 구간 구분은 일시적 오탐·반복 알림을 제한하는 구조로 유지한다. 정확도·동일인 추적·실제 출동 인수시험이 끝났다는 뜻은 아니다.
- 알림은 탐지 결과 안에서 판정하므로 실효 기준은 탐지 신뢰도와 알림 신뢰도 중 높은 값이다. 기본 탐지 10%·알림 50%·연속 3프레임·최소 반복 5초·구간 2초는 바꾸지 않는다.
- 연속 프레임은 분석된 프레임이며 3초를 의미하지 않는다. 느린 모델에서는 알림이 늦어진다. 차량만 선택한 경우 사람 자동 알림·자동 장면 저장은 없고 수동 저장은 유지한다.
- 음소거는 소리만 끄며 화면 알림·JPEG 자동 저장을 유지한다. 자동 JPEG가 실패해도 사람 후보 알림과 구간 기록은 유지하고 실패를 표시한다.
- 5초 반복은 지속 조건에서 시간당 약 720장을 만들 수 있다. 장시간 운용에서는 기존 설정의 반복 간격을 조절한다. 기본 간격 변경·자동 삭제·영상 녹화·새 위치 수집은 이번에 추가하지 않는다.

## 검증 범위

구간 전환·수신 갱신·종료 시 메모 보존, 오류 표시 유지, 음소거와 자동 저장 분리, 수동 요청 이후 프레임과 시각, 자동 JPEG 실패 시 알림·기록 보존, 사진·영상 단일 결과 버튼·원본 누락과 작은 창 배치를 검사한다. 물리 Windows 캡처보드·실제 스피커 음향은 별도 인수시험이다.

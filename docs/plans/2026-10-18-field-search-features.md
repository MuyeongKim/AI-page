## 1. 지킬 원칙

### CLAUDE.md 불변 조건 요약

- **사용자 확인 없이 바꾸지 않는 것:**
  - 모델 선택 매핑
  - 탐지 클래스(사람 `0`, 차량 `2, 5, 7`)
  - 기본값(사람+차량, 신뢰도 10%, 장치 자동, 해상도 1920)
  - 결과 저장 위치·파일명, 원본 EXIF 보존, 인증 방식, 허용 모델 정책
- **결과 무결성:**
  - 사진은 `completed`·`partial`·`failed`·`cancelled` 상태와 시도·성공·실패 수를 구분합니다.
  - 영상은 임시 파일 → 검증 → `os.replace()` 순서로 게시합니다.
  - 캡처보드의 `read=False`는 사용자 취소가 아니면 `disconnected`입니다.
- **미리보기 구조:** 최신 QImage 1장만 보관하고 GUI 스레드가 20fps로 표시합니다. 탐지·저장은 미리보기 주기와 무관하게 모든 프레임을 처리합니다.

### 이번 작업 원칙

- **기존 동작 유지:** 탐지 판단(`conf`, `classes`, `imgsz`)과 기존 결과 파일의 위치·이름은 그대로 둡니다. 새 기록 파일만 실행 폴더에 추가합니다.
- **알림·기록의 기준:** 실시간 알림과 기록표는 미리보기가 아니라 **작업 스레드의 탐지 결과**를 기준으로 합니다.
- **AI는 후보만 만듭니다:** '발견' 판정은 사람이 합니다. 어떤 기능도 자동으로 '발견' 상태를 만들지 않습니다.
- **집계 단위:** 사진 수·사람 후보 박스 수·실시간 이벤트 수·최대 동시 탐지 수를 구분합니다. 같은 사람이 여러 사진·이벤트에 등장할 수 있으므로 실제 고유 인원으로 합산하지 않습니다.
- **후보별 판단:** 사진마다 ID를 두고 사람 박스마다 별도 후보 ID와 `review`를 둡니다. 한 사진의 한 후보를 확인해도 다른 후보의 상태는 바뀌지 않습니다.
- **위치의 의미:** EXIF GPS는 `photo_gps`(촬영 위치)입니다. 사람의 정확한 위치로 표시하지 않으며, 촬영 위치 점만으로 촬영 범위·미수색 지역·수색 완료를 확정하지 않습니다.
- **시각 대응의 한계:** 가까운 촬영 시각은 대응 후보를 제안할 뿐 동일인이나 같은 지점을 증명하지 않습니다. 시간대·시계 보정·허용 간격과 `unmatched`·`uncertain` 상태를 갖추기 전에는 자동으로 교차 확인 완료·사진 미탐·촬영 범위 밖을 판정하지 않습니다.
- **새 파일 저장:** `run_report.write_run_report()`처럼 임시 파일에 쓴 뒤 `os.replace()`로 원자적으로 게시합니다. 저장에 실패하면 경고로 알리고 탐지 결과는 보존합니다.
- **개인정보:** 탐지·후보 확인·보고서 생성은 PC 안에서 처리합니다. 후보 이미지는 작게 만들고, 성명 같은 개인정보는 다루지 않습니다. 기존 GPS 지도의 배경 타일은 외부 서비스 요청이 필요하므로 오프라인 보고서와 구분하고 기존 안내를 유지합니다.
- **배포:** `mypackage/version.py`의 `CURRENT_RELEASE`를 갱신한 뒤 `python scripts/export_release.py`를 실행합니다. 기존 변경 이력은 지우지 않습니다.

## 3. 기능 목록

### 3.1 공통 (사진·실시간)

#### C1. 사진별 탐지 기록 — 1순위 (아래 기능들의 기반)

- **현재 상태:** `gui.py`의 `process_single_file()`은 사람·차량 **합계만** 누적합니다.
- **할 일:** 사진마다 다음 정보를 기록해 실행 폴더의 `detections.json`에 저장합니다([4.1 형식](#41-detectionsjson-탐지-프로그램-내부)).
  - 사람 박스(원본 픽셀 좌표)와 신뢰도, 차량 수
  - 원본·탐지본 파일명
  - EXIF 촬영 시각과 GPS
- 사진 ID·처리 상태·메타데이터 주의 사항과 사람 박스별 후보 ID·확인 상태를 함께 기록합니다. 박스 좌표와 이미지 크기는 EXIF 회전을 반영한 동일한 화면 좌표계를 사용합니다.
- **탐지가 없는 사진:** 시각과 GPS만 기록합니다. P2 촬영 범위와 L4 크로스체크에 필요합니다.
- **완료 기준:**
  - 탐지 판단이 바뀌지 않습니다.
  - 원자적으로 저장하고, 실패하면 경고만 내고 결과는 보존합니다.
  - 기존 `original_*`/`detected_*` 번호 규칙을 유지합니다.
  - 테스트를 추가합니다.
- **관련 코드:** `gui.py` `process_single_file()`, `run_report.py`, `gps2.extract_gps_data()`

#### C2. 후보 확인 모드 — 1순위

- 후보(사진의 각 사람 박스, 실시간 이벤트)를 키보드로 넘기며 **사람 맞음 / 오탐 / 보류**로 표시합니다. 예: `←`·`→`로 이동, `1`·`2`·`3`으로 표시. 실제 고유 인원이나 현장 발견 확정으로 해석하지 않습니다.
- 표시 결과는 `detections.json`(실시간은 L2 기록)과 보고서에 반영합니다. 원본 사진은 수정하지 않습니다.
- **완료 기준:**
  - 마우스 없이 키보드만으로 조작할 수 있습니다.
  - 다시 열어도 표시 결과가 유지됩니다.
  - 확인 수와 오탐 수를 집계합니다.
- **관련 코드:** `result_view.py`의 `ResultComparisonDialog`, `PhotoPreview`

#### C3. 사람 부분 확대 이미지 — 1순위

- 4000×3000 사진에서 사람은 수십 픽셀이라, 사진 전체를 줄인 썸네일로는 보이지 않습니다.
- 박스 주변을 여백까지 포함해 잘라 확대합니다. 예: 박스 크기의 3배 영역, 최소 크기를 보장합니다.
- 좌표를 이미지 경계로 제한하고 EXIF 회전·미러링을 검증합니다. 확대는 원본 픽셀을 표시하는 기능이며 새로운 세부 정보를 복원하지 않습니다.
- 이 이미지를 확인 화면, 보고서 썸네일, 상황판 후보 파일(S1)에 씁니다.

#### C4. 보고서 자동 생성 — 1순위

- **사진 보고서:** 처리 사진 수, 후보 수, 확인 결과, 신뢰도 높은 순 후보 확대 이미지(C3), 촬영 위치(가능할 때), 소요 시간, 설정값을 넣습니다.
- **실시간 보고서:** L2 기록표를 바탕으로 한 **1차 수색결과보고** 요약입니다.
- **형식:** 이미지를 포함한 HTML 한 파일입니다. 오프라인으로 열려야 하고, 인쇄하면 A4 1~2쪽이 되게 합니다.
- 요약은 1~2쪽을 목표로 하고 후보가 많으면 전체 목록을 부록으로 구분합니다. 후보를 조용히 누락하지 않으며, 촬영 위치와 집계 단위를 명시하고 오류·부분 완료·미확인을 보존합니다.

#### C5. 결과 압축 내보내기 — 3순위

- 보고서, 후보 이미지, 지도를 압축 파일 하나로 묶습니다.

#### C6. 야간 화면 — 3순위

- 야간 CP용 어두운 테마를 추가합니다.

#### C7. 노트북 배터리 경고 — 3순위

- 분석 중 배터리가 20% 아래로 내려가면 전원 연결을 안내합니다.
- `psutil.sensors_battery()`를 쓰고, 배터리 정보가 없는 PC에서는 표시하지 않습니다.

### 3.2 사진 전용

#### P1. SD카드 통째로 넣기 — 1순위

- **현재 상태:** `gui.py`의 `count_image_files()`가 `folder.glob("*")`라 하위 폴더를 읽지 않습니다.
- **할 일:** 하위 폴더까지 읽습니다. DJI 기체는 비행마다 하위 폴더를 만듭니다.
- 선택 시 사진 수 계산과 실제 처리에 같은 탐색 규칙을 사용합니다. 심볼릭 링크 순환·중복 선택과 프로그램 결과 폴더의 재분석을 방지하고 읽기 실패를 안내합니다.
- **완료 기준:** 서로 다른 폴더에 같은 파일명(`DJI_0001.JPG` 등)이 있어도 결과 이름이 충돌하지 않는지 테스트로 확인합니다.

#### P2. 촬영 범위 지도 — 2순위

- 촬영한 사진 전체의 촬영 위치를 점으로, 후보 사진의 위치는 강조해서 표시합니다. 사진 위치가 없는 곳은 기록 공백으로만 보여 줍니다. 촬영 발자국·카메라 방향 등 근거 없이 미수색 지역이나 수색 완료를 판정하지 않습니다.

#### P3. 좌표 복사·휴대폰 지도 링크 — 2순위

- 후보 사진의 촬영 좌표(십진 위경도)를 클릭 한 번으로 복사하며, 사람의 정확한 좌표가 아님을 표시합니다.
- 지상팀 휴대폰용으로 지도 앱 링크를 만듭니다. 링크 형식은 각 지도 서비스의 공식 안내로 확인합니다. 예: 카카오맵 `https://map.kakao.com/link/map/이름,위도,경도`

#### P4. 고도 경고 — 3순위

- 2024-10 실측 한계(광각 70m, 열화상 45m)를 넘은 사진에 "AI 신뢰 낮음, 육안 확인 필요"를 표시합니다.
- **주의:** EXIF `GPSAltitude`는 해발고도입니다. 기체의 상대고도는 DJI XMP `RelativeAltitude`처럼 기종마다 위치가 다릅니다. Evo2pro와 매빅3T 샘플로 확인합니다. 열화상 사진을 구분하는 방법(예: 640×512 크기)도 확인이 필요합니다.

#### P5. 이미 분석한 사진 건너뛰기 — 3순위

- 판별 기준(파일명+크기+촬영 시각, 또는 해시)을 정합니다.
- 건너뛴 사진 수를 사용자에게 보여 줍니다.

#### P6. 오프라인 대비 — 3순위

- 인터넷이 없어 지도 배경이 뜨지 않으면 좌표 목록으로 대신 보여 주고 안내합니다.

#### P7. 옷 색 우선 정렬 — 3순위 (S2 연계)

- 인상착의 색과 비슷한 후보를 **앞으로 정렬만** 합니다. 후보를 빼지는 않습니다.
- 열화상 사진에는 적용하지 않습니다.

### 3.3 실시간(캡처보드) 전용

#### L1. 탐지 알림 — 1순위

- 사람이 잡히면 소리와 화면 테두리 깜빡임으로 알리고, 음소거 버튼을 둡니다.
- **오알림 억제:**
  - N프레임 연속으로 잡혔을 때만 알립니다.
  - 같은 알림은 일정 간격 안에 반복하지 않습니다.
  - 알림 기준 신뢰도를 따로 둡니다. 탐지 기준 10%는 그대로 유지합니다.
- **완료 기준:** 작업 스레드의 결과를 기준으로 동작하고, 미리보기 20fps 구조에 영향을 주지 않습니다.
- **관련 코드:** `gui.py`의 `process_video()`(비디오·캡처보드 공용), `open_video_capture()`

#### L2. 실시간 탐지 기록표 — 1순위 (사용자 제안)

- **한 줄 묶기:** 연속으로 잡힌 구간은 한 줄로 묶습니다. 끊긴 시간이 2초 이내면 같은 이벤트로 보고, 이 값은 설정할 수 있게 합니다.
- 같은 이벤트는 시간 구간을 묶은 것이며 같은 사람을 추적했다는 뜻이 아닙니다. 알림과 기록은 공통 이벤트 상태를 사용하고 연결 끊김·취소·실패 시 열린 구간을 마감해 보존합니다.
- **칸:**
  - 번호, 시작·종료 시각, 지속(초), 최고 신뢰도, 최대 인원
  - 메모(견시자 입력, 예: "C3 쪽")
  - 장면 파일(L3 승인 시)
  - 착륙 후 채우는 칸(L4)
- **내보내기:**
  - CSV: 엑셀에서 한글이 깨지지 않게 **UTF-8 BOM**으로 저장합니다.
  - 복사용 보고 문구. 예: `14:32 C3 구역 사람 후보 1명, 4초간 탐지`
  - C4 보고서
- **완료 기준:** 연결 끊김(`disconnected`)이나 취소가 나도 그때까지의 기록을 보존합니다.

#### L3. 장면 캡처 저장 — 1순위, **2026-10-18 사용자 승인 완료**

- 알림이 울린 장면을 자동 저장하고, 견시자가 스페이스바로 직접 저장할 수도 있게 합니다.
- 사용자 승인 범위는 실행 폴더의 정지 이미지 자동·수동 저장입니다. 캡처보드 영상 녹화는 추가하지 않습니다. 취소·연결 끊김에도 이미 저장된 장면은 보존합니다.
- 화면 전체를 저장하면 조종기 화면의 고도·거리·미니맵도 함께 남습니다.

#### L4. 사진 크로스체크 — 2순위

- **시각 맞춤:** 착륙 후 사진(C1)을 분석할 때, L2의 각 이벤트를 가장 가까운 시각에 찍힌 사진과 맞춥니다.
- **채우는 칸:** 매칭 사진, 위경도, 격자 칸(상황판 좌표 보정 파일이 있을 때), 크로스체크 결과
- **크로스체크 결과:** `대응 후보 있음 → 사람 확인 필요` / `매칭 없음` / `대응 불확실`을 기본으로 합니다. 동일 장면·촬영 범위를 확인한 근거가 있을 때만 `사진에서도 탐지`·`사진 미탐`·`촬영 범위 밖`으로 구분합니다.
- **반대 방향:** 사진에서만 잡히고 실시간에서는 놓친 후보 목록을 따로 만듭니다.
- **시계 차이 보정:** 사람이 대응을 확인한 복수 표본이 있을 때만 추정하며 보정값·오차·표본 수를 표시합니다. 먼저 수동 보정과 허용 시간 간격을 지원하고, 근거가 부족하면 자동 추정을 하지 않습니다.
- **주의:** EXIF `DateTimeOriginal`에는 시간대 정보가 없을 수 있습니다. 드론 시계 설정을 확인합니다.

#### L5. 전체화면·보조 모니터 출력 — 3순위

- 탐지 박스가 있는 화면을 지휘차 TV 등 보조 모니터에 띄웁니다.

#### L6. 연결 끊김 시 자동 재연결 — 3순위

- 끊긴 이력은 `disconnected`로 남기고, 다시 연결되면 기록표를 이어서 씁니다.
- 상태 설계가 불변 조건과 충돌하지 않는지 사용자와 먼저 확인합니다.

### 3.4 상황판(STAY UP) 연계 — 저장소 `/Users/tenmoo/stayup-dash`

- **상황판 현황:** 단일 HTML, 오프라인 우선, localStorage·IndexedDB 저장입니다. README에 "훈련·시연용, 실출동 단독 운용 승인 전"이라고 적혀 있으므로, 지원서에 실사용으로 쓰지 않습니다.
- **상황판 작업 규칙:**
  - `python3 -m http.server 8899 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:8899/tests/regression.html`을 엽니다. **265건이 모두 통과하기 전에는 커밋하지 않습니다.**
  - 상태 구조를 바꾸면 `STATE_VERSION`, 불러오기 검증, 내보내기, 회귀검사를 함께 갱신합니다.
  - 상태를 자동으로 바꾸지 않습니다. 기존 "불일치 감지 + 원클릭 반영" 방식을 따릅니다.

#### S1. AI 후보 보내기 (탐지 → 상황판) — 2순위

- **탐지 프로그램:** "상황판으로 보내기"를 누르면 `stayup-ai-candidates.json`을 만듭니다([4.3 형식](#43-stayup-ai-candidatesjson-탐지--상황판-공통)).
- **상황판:** 기존 끌어다 놓기(지도·좌표 파일) 흐름으로 파일을 받습니다.
  - **AI 후보 핀:** 미확인은 ○, 사람 확인은 ●로 표시하고 오탐은 숨깁니다. 좌표 보정(`grid.geo`)이 있을 때만 지도에 배치하고, 없으면 목록으로만 보여 줍니다.
  - **격자 칸 이름:** 핀마다 칸 이름(예: C3)을 붙입니다.
  - **타임라인:** 새 유형 'AI 후보'로 한 줄 기록합니다. 예: "AI 분석: 사진 820장, 후보 5건(확인 2건)". 기존 '발견'·'열원감지' 유형과 구분합니다.
  - **촬영 범위 반영 제안:** 촬영 범위로 "C3·C4 드론 촬영됨"을 제안하고, 반영은 사람이 한 번 눌러서 합니다.
  - **발견 승격:** 후보를 사람이 '발견'으로 올릴 때만 기존 발견 핀·경보가 작동합니다.
- **입력 검증:**
  - 형식명과 버전이 맞지 않으면 거부합니다.
  - 위경도 범위를 확인합니다.
  - 파일 크기를 제한합니다. 상황판 JSON 입력 한도는 24 MiB이고, 후보 이미지는 각 30KB 안팎을 권장합니다.

#### S2. 인상착의 색 가져오기 (상황판 → 탐지) — 3순위

- 상황판 JSON 내보내기 파일에서 `subject.topColor`와 `subject.botColor`**만** 읽습니다. 최상위 구조는 상황판의 `exportPayload()`를 확인합니다.
- 성명이나 특이사항 같은 다른 정보는 읽지 않습니다. 읽은 색은 P7 정렬에 씁니다.

#### S3. 실시간 후보 배너 (실시간 → 상황판 표출 화면) — 3순위

- 탐지 프로그램이 같은 PC의 지정 폴더에 이벤트 파일을 씁니다.
- 상황판은 폴더 접근 권한(File System Access)으로 그 폴더를 감시하고, 표출 화면에 "AI 사람 후보" 배너를 띄웁니다. 발견 경보와는 다른 단계입니다.
- 기존 "보관 파일 지정"과 같이, 새로고침하면 폴더를 다시 지정해야 합니다.

## 4. 데이터 형식 (초안 v1)

- 초안이므로 구현하면서 바꿀 수 있습니다. 다만 **4.3은 두 저장소에서 함께 바꿉니다.**
- 이름 규칙: 탐지 프로그램 내부 파일은 snake_case, 상황판과 주고받는 파일은 camelCase입니다.
- 예시의 좌표·파일명은 형식 설명용입니다. 실제 파일명 규칙은 현재 코드를 따릅니다.

### 4.1 `detections.json` (탐지 프로그램 내부)

```json
{
  "schema_version": 1,
  "photos": [
    {
      "id": "photo-000001",
      "status": "completed",
      "source": "DCIM/DJI_001/DJI_0123.JPG",
      "original_file": "original_0003.jpg",
      "detected_file": "detected_0003.jpg",
      "captured_at": "2026-10-20T14:21:08",
      "gps": {"lat": 35.0, "lon": 127.0},
      "location_kind": "photo_gps",
      "image_size": [4000, 3000],
      "people": [{"id": "photo-000001-person-001", "confidence": 0.42, "box": [1830, 1210, 1862, 1288], "review": "unreviewed"}],
      "vehicles": 0,
      "warnings": []
    }
  ]
}
```

- `people[].review` 값: `unreviewed` | `person` | `false_positive` | `hold`. 사진 전체에 판정 하나를 두지 않고 후보마다 저장합니다.
- 탐지가 없는 사진은 `people: []`로 두고, 원본·탐지본 파일 칸은 비웁니다.

### 4.2 실시간 기록표 (`live_events.csv`, `live_events.json`)

CSV는 UTF-8 BOM으로 저장합니다. 칸 이름은 다음과 같습니다.

```text
번호, 시작 시각, 종료 시각, 지속(초), 최고 신뢰도, 최대 인원, 메모, 장면 파일,
매칭 사진, 위도, 경도, 격자 칸, 크로스체크
```

### 4.3 `stayup-ai-candidates.json` (탐지 → 상황판 공통)

```json
{
  "format": "stayup-ai-candidates",
  "version": 1,
  "generatedAt": "2026-10-20T14:40:00+09:00",
  "app": {"name": "STAY UP AI", "version": "26.xxxx"},
  "run": {"input": "photo", "photoCount": 820, "startedAt": "...", "finishedAt": "..."},
  "candidates": [
    {
      "id": "p-0003",
      "source": "photo",
      "capturedAt": "2026-10-20T14:21:08+09:00",
      "lat": 35.0,
      "lon": 127.0,
      "confidence": 0.42,
      "people": 1,
      "review": "person",
      "crosscheck": "confirmed",
      "file": "detected_0003.jpg",
      "thumbnail": "data:image/jpeg;base64,..."
    }
  ],
  "coverage": [{"lat": 35.0, "lon": 127.0, "capturedAt": "..."}]
}
```

- `source` 값: `photo` | `live`
- `crosscheck` 값: `confirmed`(실시간·사진 모두) | `photo_missed`(실시간만) | `live_missed`(사진만) | `out_of_range` | `null`
- 실시간 후보는 L4 크로스체크 전이라 위경도가 없을 수 있습니다. 이때는 `lat`·`lon`을 `null`로 두고, 상황판은 지도 대신 목록에만 표시합니다.

## 5. 도전 과제 (본선 이후 검토)

- **작은 사람 탐지 향상(사진 분할 분석):** 탐지 판단이 바뀌므로 기본값은 두고 선택 옵션으로만 넣습니다. 2024 실측 한계인 70m를 넘길 수 있는지 다시 측정합니다.
- **유류품 탐지(배낭·우산·가방):** 탐지 클래스 정책이 바뀌므로 사용자 승인이 필요합니다. 항공 사진의 오탐을 먼저 시험합니다.
- **사람 후보의 실제 좌표 추정:** 고도·카메라·방위 정보로 사진 속 위치를 계산합니다. 기종별 메타데이터 차이와 정확도를 검증해야 합니다.

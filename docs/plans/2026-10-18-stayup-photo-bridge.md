# 사진 후보 파일 연계 1단계

2026-10-18 사용자 승인: 현장에 따라 같은/다른 PC를 사용하므로 오프라인 파일 전달을 기본으로 한다. 사진 후보 내보내기를 먼저 구현하고, 상황판의 온라인 지도 작업이 커밋된 뒤 가져오기를 반영한다. AI-page는 V26.1018을 유지한다.

- 기존 상황·인원·기체·지도·수색 상태·발견 핀·대응 기록을 유지한다. 상황 백업 복원과 AI 후보 추가/갱신은 별도 동작이다.
- 공통 파일: `stayup-ai-candidates.json`, 형식명 `stayup-ai-candidates`, 버전 1. 사용자가 저장 위치를 선택한다. 작은 JPEG 미리보기를 포함해 다른 PC에서도 읽는다.
- 분석 기록에 영구 작업 UUID와 내보내기 리비전/내용 지문을 보관한다. 기록 폴더를 복사해도 작업 ID를 유지하고 판정 변경 시 리비전이 증가한다. 같은 내용 재전달은 중복 생성하지 않으며 과거 리비전은 거부한다.
- 후보 ID는 작업 ID와 결합한다. 원본 판정 갱신과 상황판의 대응 상태·메모는 분리한다. 원본 후보가 빠져도 대응 이력을 지우지 않는다.
- GPS는 사진 촬영 위치다. 같은 사진의 후보는 지도에서 묶고, GPS 없음·지도 미보정·범위 밖은 목록과 상태로 표시한다. 발견·수색 완료로 자동 전환하지 않는다.
- 후보 이미지는 브라우저의 별도 이미지 저장소에 보관하고 백업·복구·완전삭제에 포함한다. 미리보기 읽기 실패, 저장 실패, 늦은 파일 읽기와 상황 전환은 명시적으로 처리한다.
- 테스트 우선: 내보내기 안정 ID·리비전·경로/파일 제한·쓰기 실패, 가져오기 상태 보존·중복/과거/충돌 갱신·대응 보존·이미지/백업·좌표·두 창·실제 파일 선택을 검증한다.
- 실시간 폴더 읽기·다른 PC 자동 전송·실시간 좌표 OCR은 이번 범위 밖이다. UI 없는 영상 운용을 확인했으므로 좌표 OCR은 보류한다.

## 공통 형식 v1

`format`, `version`, `generatedAt`, `app: {name, version}`, `run: {id, revision, status, photoCount, completedCount, failedCount}`, `candidates`를 사용한다.

각 후보는 `id`, `photoId`, `file`(파일명만), `capturedAt`(없거나 시간대 미상이면 그대로 보존), `gps`(없으면 null), `locationKind: photo_gps`, `confidence`, `review`, `box`, `imageSize`, `thumbnail`(JPEG data URL 또는 null)을 갖는다. 파일은 16 MiB, 후보 5,000건, JPEG 한 장 32 KiB 이하로 제한한다. 형식/숫자/좌표/ID 중복/이미지를 검증한 뒤 한 번에 반영한다.
